# Harbor Loop V0.11.0 — Combo Racers

微信小游戏 / 浏览器玩法原型。原生 Canvas 2D，无游戏引擎依赖。

## 当前版本

**只开放 Combo Racers 一个模式**：限时 60 秒，比谁的最大连击数高。撞车断连击，但不清除记录。

其余 15 个模式已实现并有测试覆盖，通过 `src/modes/index.ts` 的 `RELEASED_MODE_IDS` 控制放出 —— 一次给 16 个反而埋掉了游戏真正的核心。

### 速度曲线

**每超一辆车都加速**，且递减：

| 连击区间 | 每辆加速 |
|---|---:|
| 1–10 | +6.0 |
| 11–25 | +3.0 |
| 26–50 | +1.5 |
| 51+ | +0.55 |

巡航上限 380，按住油门再加 60。加速感集中在开局，中后期是缓慢爬升而不是突然窜出去。

### 其他

- 5 条车道，开局 3-2-1 倒计时（期间世界完全静止）
- HUD 只显示最大连击数；当前连击数每次超车在车上弹一下即消失
- 母车残影、过弯胎噪、三层撞车音
- 车辆为启动时程序生成的预渲染精灵（10 倍超采样），路面有沥青颗粒贴图 —— 不使用任何外部图片，包体不增加
- 日间码头配色：浅混凝土路面 + 黄褐色边线 + 淡蓝灰水面 + 橄榄绿岸地
- 港口场景：礁石岸线、码头建筑、黑白格起跑区、栈桥、停泊游艇
- 俯角相机（近远缩放比 1.46），有体积感且远端车流可读；每条赛道投影后自动缩放以保证不出屏
- 五条车道以一深一浅交替填充区分，不用虚线分道线

### 模式

前 7 个是 Q-Games《PixelJunk Racers》有公开资料记载的模式（菜单里带 `PJ` 标记）；
后 9 个没有任何公开资料记载具体规则，是用同样的"换道 / 油门 / 超车"三个动词原创的。

| 模式 | 来源 | 规则 |
|---|---|---|
| SPEED MONKEY | PJ | 速度只增不减，撞一次就结束 |
| COMBO RACERS | PJ | 限时 60 秒把 Combo 冲到 40，撞车清零 |
| SUNDAY DRIVERS | PJ | 车流极慢，限时超越尽可能多的车 |
| FIREBALL FRENZY | PJ | 每 10 次超车化身火球，火球状态撞车即摧毁 |
| DEATH RACE | PJ | 限时 90 秒撞毁场上全部车辆 |
| IN THE ZONE | PJ | 跟住 6 辆标记车的尾流区域，待满即清除 |
| HOT RODS | PJ | 油门会过热，限时跑出最远距离 |
| SLIPSTREAM | 原创 | 贴住前车蓄力，满蓄时超车得双倍分 |
| GHOST LANE | 原创 | 每隔几秒一条车道带电，提前 1.2 秒预警 |
| RUSH HOUR | 原创 | 车流持续提速 |
| PACE SETTER | 原创 | 把车速保持在移动的目标区间内 |
| LAST MAN | 原创 | 对手每 4 秒自爆一辆，车越少分越难拿 |
| CHAIN REACTION | 原创 | 5 次超车装填，每次摧毁刷新 3.2 秒窗口 |
| BLACKOUT | 原创 | 每 7 秒熄灯 2 秒，靠记忆穿过车流 |
| TIME ATTACK | 原创 | 跑完 3 圈，用时越短越好 |
| ENDURANCE | 原创 | 无时间限制，一条命，车流永远在加速 |

### 赛道

四条赛道，每个模式绑定一条，所以换模式就换场地，不需要额外的选择界面：

| 赛道 | 圈长 | 特点 | 使用的模式 |
|---|---:|---|---|
| LONG BAY | ~2990 | 8 段长直道 + 宽发夹，圈最长，适合堆 Combo | Speed Monkey、Combo Racers、Fireball Frenzy、Chain Reaction、Endurance |
| GRAND OVAL | ~1390 | 体育场式，只有两个弯，全程高速无处躲 | Sunday Drivers、Rush Hour、Pace Setter、Time Attack |
| SWITCHBACK | ~2100 | 9 段短直道 + 密集发夹，弯道不断，车道选择最关键 | In The Zone、Hot Rods、Slipstream、Blackout |
| MARINA SPRINT | ~2200 | 中等圈长，宽弯，节奏快但有喘息空间 | Death Race、Ghost Lane、Last Man |

赛道用精确的直线和圆弧构造，曲率连续；景观装饰按赛道分别定义，不会压在路面上。

### 难度

**只有一档**，没有难度选择。让玩家在开出第一圈之前选难度，是一个谁都做不好的选择。

| | STANDARD |
|---|---:|
| 玩家速度 | ×1.00 |
| 车流速度 | ×1.00 |
| 车辆数 | 24 |
| AI 让路区域 | ×0.75 |
| 同时并线的 AI | 3 |
| 撞车后无敌时间 | 1.15s |

车流按黄金比例分布在整圈上，所以任意车辆数都不会扎堆。

**起步速度 125，最快的 AI 是 117** —— 这个差距是故意留窄的。超车必须靠走位换来，
而速度全部来自 Combo：前 10 次超车每次 +6，之后递减。一局的加速曲线由玩家自己拉出来，
不是开局就给满。撞车清空 Combo，也就清空了你攒下来的速度。

`Difficulty` 保留成类型而不是直接删掉：成绩在本地存档和云端榜单里仍按
`模式:难度` 分区，所以以后要加回第二档只是改数据，不用做数据迁移。

### 界面

菜单和结算页按微信休闲爆款那套视觉重做：饱和底色 + 米白卡片、粗描边、硬投影（不用模糊），
主操作用一个高饱和暖色独占。比赛画面保持原来的海港配色不变。

### 每日挑战

菜单顶部的独立入口，不受解锁限制。

- 每天固定一个模式 + 一份车流种子，**全服完全一致**，分数直接可比。
- 分两关，两关跑同一个车流（只有一档难度），落差全在目标分上：第一关铜星线，大多数人能过；第二关金星线 ×1.45，设计成极少数人能过。过第一关直接进第二关。
- 成绩写入按日期分区的独立榜单，不影响各模式的最好成绩。
- 所有影响模拟的随机数都走种子发生器（`src/rng.ts`），因此同一天所有人开出来的车流一模一样。

### 新手引导与连续天数

- 第一局会显示控件提示，用过即消失，永久只出现一次。
- 菜单头部显示连续游玩天数（断一天归零）。

### 排行榜与分享

- 每个（模式 × 难度）单独记录个人最好成绩，存在本地。
- 全部最好成绩之和作为"生涯积分"，通过 `wx.setUserCloudStorage` 上传。
- 好友排行榜由开放数据域子包 `openDataContext/` 渲染，结算页直接贴上共享画布。
- 全服排行榜走**微信云开发 CloudBase**（`cloudfunctions/` 下的 `submitScore` / `topScores` 两个云函数 + `harbor_scores` 集合）。开放数据域只能读好友数据，全服榜必须有真正的存储。结算页的排行榜卡片可在「好友 / 全服」之间切换。
- 云环境 ID 填在 `src/cloud.ts`；留空时游戏照常运行，只是全服榜显示未配置。部署步骤见 `WECHAT_ONBOARDING.md` 的「J. 云开发」。
- 结算页有分享按钮；分享时会离屏绘制一张 5:4 的成绩卡（品牌、模式、难度、大号分数、星级、赛道轮廓）作为卡片配图。
- **分享复活**：撞毁或超时后每局一次，分享即可续上同一局。
- 菜单头部有静音开关，偏好持久化。
- 以上三项都只在微信小游戏内生效，浏览器预览会自动降级。

## 开发

源码在 `src/`（TypeScript），由 esbuild 打包成根目录的 `game.js`。**不要直接改 `game.js`，它是生成文件。**

```bash
npm install
npm run build     # src/ -> game.js
npm run watch     # 改动自动重新打包
npm run check     # tsc 类型检查
npm test          # 打包 + 跑无头输入测试
npm run verify    # check + test
```

`game.js` 会提交进仓库，因此微信开发者工具导入后可以直接编译，不需要先装依赖。改完代码记得 `npm run build` 再提交。

### 目录结构

| 路径 | 内容 |
|---|---|
| `src/main.ts` | 入口：帧循环和三个界面的切换 |
| `src/app.ts` | 界面状态机：菜单 / 比赛 / 结算 |
| `src/modes/` | 16 个模式，一个模式一个文件 + 注册表 |

| `src/screens/` | 模式选择和结算界面 |
| `src/storage.ts` `src/leaderboard.ts` `src/share.ts` | 成绩存档、好友榜、分享 |
| `src/platform.ts` | 唯一直接调用 `wx` 的模块；画布、缩放、震动、音频上下文 |
| `src/config.ts` | 全部玩法数值（车道、速度档、AI、碰撞） |
| `src/track.ts` | 赛道几何与沿路面推进的距离计算 |
| `src/state.ts` | 玩家和 AI 的可变状态、速度档查询 |
| `src/player.ts` `src/ai.ts` `src/scoring.ts` | 玩家行为、AI 行为、碰撞与超车计分 |

| `openDataContext/` | 开放数据域子包，独立 JS 环境，只负责画好友榜 |

## V0.9.5 重点

手机端补上了缺失的一半玩法：屏幕底部加入三个可见按键，触屏也能加油门。

- 底部控制条：左变道、右变道、油门（按住加速，松开回落）。
- 手机端在此之前只能变道，速度完全被动；现在触屏和键盘玩法一致。
- 按键放在赛道下方的空白区，不遮挡路面和车辆；下边缘留出 iPhone 手势区。
- 支持多点触控：一根手指按住油门，另一根手指点变道，油门不会断。
- 手指从油门键滑走会松油门，滑回来重新加速，不会卡在持续加速状态。
- 赛道区域保留原来的左右半屏点击变道，老的单手玩法照常可用。

## V0.9.4 重点

V0.9.4 根据实际试玩反馈重新设计速度曲线：普通超车只累计 Combo，永久速度只在每 10 辆时提升一档。

- 开局巡航速度保持 125，玩家仍需主动按油门追车。
- `x10 / x20 / x30...` 会触发一次明显的永久提速。
- 速度提升在约 0.4–0.7 秒内完成，不是瞬间跳帧，也不再分摊成每辆车几乎感觉不到的小幅增长。
- `x70` 巡航速度达到 515，按住油门可达 600；相比 V0.9.3 的 293/338 明显更快。
- 最高速度提高至 705，后期是真正的高速读车流阶段。
- 每 10 辆同时提高发动机基础转速，油门负责当前档位内的转速拉高与回落。
- 发动机由三层机械谐波与滤波噪声组成，减少之前单个合成器音符的感觉。
- 高速阶段扩大 AI 禁止变道安全区。
- 新增高速穿越检测，低帧率下红车不能直接穿过同车道黑车而漏判碰撞。
- 保留 V0.9.1 的六车道真实路面速度修复。

## 速度规则

| Combo | 松开油门巡航 | 按住油门最高 |
|---:|---:|---:|
| 0–9 | 125 | 175 |
| 10–19 | 180 | 240 |
| 20–29 | 240 | 310 |
| 30–39 | 305 | 380 |
| 40–49 | 365 | 445 |
| 50–59 | 420 | 505 |
| 60–69 | 470 | 555 |
| 70–79 | 515 | 600 |
| 80–89 | 555 | 640 |
| 90–99 | 590 | 675 |
| 100+ | 620 | 705 |

普通超车不会永久提高目标速度。跨过十辆节点后，红车使用更强的短时加速度追向新档位；因此 `x9 → x10`、`x19 → x20` 等节点应有清楚体感。

## 操作

### 浏览器 / 键盘

- `← / →` 或 `A / D`：即时变道。
- 按住 `↑`、`W` 或 `Space`：加油门。
- 松开油门键：回落到当前档位的巡航速度。
- `R`：重新开始。

### 微信触屏

底部三个可见按键：

- `◀` / `▶`：变道，点一下走一条车道。
- `GAS`：按住加油门，松开回落到当前档位的巡航速度。
- 可以一根手指按住 `GAS`，另一根手指点变道键。
- 赛道区域（按键上方）仍然支持点击左半边 / 右半边变道。

## 声音逻辑

发动机现在包含：

1. 低频三角波，负责发动机主体。
2. 经过滤波的中频锯齿层，负责机械颗粒。
3. 较轻的高频谐波与带通噪声，速度和油门越高越明显。

发动机基础转速只在每 10 Combo 提高；按住油门会在当前档位内升转，松开后回落。所有声音均为运行时程序合成，没有打包或复制原版游戏音频。

## 建议测试

1. 开局按住 `Space`，确认 125 → 175 的加速比 V0.9.3 更明确。
2. 观察 `x9 → x10`：车速和发动机基础转速应同时明显提升。
3. 继续到 `x30`，确认游戏已经进入明显高速状态。
4. 到 `x70`，确认红车速度显著高于 V0.9.3，而不是仍像中速巡航。
5. 在高 Combo 故意保持同车道追上黑车，确认不会因帧率而穿车。
